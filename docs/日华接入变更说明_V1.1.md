# 806 储值战报 V1.1｜日华接入变更说明

## 本轮页面变化

- 底部全门店总表改为只读，不再点击跳转；顶部两级选择器、区域排名、冲刺榜和关注榜仍可进入详情。
- 区域和门店首屏会根据当前今日／累计口径，计算严格超过上一名达成率所需的最小整数金额。
- 门店反超金额以全国榜为主，区域内排名只做辅助展示。
- 今日或累计的全国／区域第一都可触发冠军首屏，头衔会写明具体榜单，不使用全屏庆祝动画。
- 冠军首屏改为局部品牌红＋香槟金，不影响下面标准数据版式；范围选择压缩为轻量控制栏，让核心数据更早出现。
- 排名对比文案统一使用“今日比总进度领先／落后X名”。
- 奖金区显示“已获得奖金＋挑战目标还差多少”。当前BI没有固定的100%总奖金，页面不做估算。

## `ReportPayloadV1` 兼容扩展

`schemaVersion` 仍为 `1`，`Store` 和 `Region` 新增可选字段：

```json
{
  "rankChanges30": {
    "cumulativeChallenge": 2,
    "todayChallenge": -1
  }
}
```

技术中心若确认“完成目标可拿固定总奖金”，可再返回：

```json
{
  "bonusGoal": {
    "label": "完成挑战目标",
    "targetAmount": 116475,
    "totalBonus": 1200
  }
}
```

`bonusGoal` 缺失时页面会安全回退为目标差额提示，不会按现有档位占比猜测总奖金。

- 正数：近30分钟排名上升。
- 负数：近30分钟排名下降。
- `0`：排名持平。
- `null`：没有符合时间窗口的可比快照。

`Store.rankChange30` 暂时保留，继续表示累计排名变化，旧页面不会因此报错。新页面优先读取 `rankChanges30`，字段缺失时显示“待下次快照”。

## 接口迁移注意

- 正式接口仍返回完整 `ReportPayloadV1`，不需要为 V1.1 新建页面或新接口。
- “超越上一名所需金额”由前端使用当前榜单中双方的金额和目标实时计算，后端无需新增派生字段。
- 区域内门店排名由前端按 BI 全国排名顺序过滤后计算，可继承 BI 对并列情况的顺序。
- 接口失败时仍保留最后一次成功数据，不得将金额、排名或反超差额清零。
