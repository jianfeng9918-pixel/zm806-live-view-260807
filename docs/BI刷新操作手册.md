# 806 战报第一阶段刷新操作手册

## 用户需要做什么

1. 在 Chrome 登录周麻婆 BI。
2. 保持电脑开机、联网，并让 Chrome 中的 BI 登录保持有效；定时任务将在整点和半点自动执行。
3. 若登录失效、出现验证码或 BI 改版，由用户完成登录或确认，不向 Codex提供密码、验证码。

## Codex 更新步骤

1. 打开 `15_2026版_806活动储值分析`。
2. 进入“导出 → 批量导出 Excel”，只选择下列5张门店／区域必需表，禁止点击“全选”：
   - `门店_总储值目标达成率`
   - `门店_今日目标达成率排行`
   - `门店_目标达成与奖金`
   - `销售地区_今日储值目标达成率`
   - `销售地区_目标达成与奖金`
3. 使用“直接导出 → 保存为多个sheet”，导出门店／区域轻量Excel。
4. 切换到 `16_26年版_806会员储值清单与职能目标`，再次进入批量导出，只选择下列2张表，仍然禁止点击“全选”：
   - `职能部门_储值目标达成率`
   - `集团总目标_2026806`
5. 使用“直接导出 → 保存为多个sheet”，导出职能校验Excel。两个文件应在同一轮连续导出；门店／区域文件正常约43KB，职能文件约7KB。
6. 核对门店／区域工作簿必须包含100家以上门店和10个以上区域；职能工作簿必须包含完整职能部门汇总、职能端／门店端／集团总计。禁止用当前屏幕可见行或截图替代完整导出。
7. 定时任务将两个下载文件同时交给以下入口，成功后原下载文件移入废纸篓，原始副本和计算快照保留在本地且不公开：

   ```bash
   npm run data:ingest -- \
     --input "/Users/huangjianfeng/Downloads/本次门店区域导出.xlsx" \
     --functional-input "/Users/huangjianfeng/Downloads/本次职能导出.xlsx" \
     --trash-source
   ```

8. 入口会自动执行完整验证，检查5＋2张表、门店数、区域数、职能分项、集团总计、规则与构建；任一步失败都不发布。
9. 成功后仅更新公开网页所需的 `public/data/report.json`，GitHub Pages完成发布后，已打开的手机页面会在1分钟内发现新版本并刷新数据。

## 总部与排名口径

- 总部“今日储值金额”＝门店端今日金额＋职能端今日金额。
- 总部“累计储值金额”＝门店端累计金额＋职能端累计金额，并用 `集团总目标_2026806` 的集团总计做交叉校验。
- 总部累计挑战目标＝门店挑战目标＋职能目标；职能BI暂无每日目标，因此今日目标金额仍使用门店端BI目标，职能今日金额只并入总部今日实绩。
- 职能数据不进入区域或门店排名，不进入最快门店、待督促、参与门店数和全部门店列表。
- 新口径上线后的第一次快照不与旧的“仅门店”总部快照计算30分钟增长，待下一次新口径快照后恢复总部增量。

## 近30分钟口径

- 当前快照优先匹配距它 20–40 分钟内、时间最接近 30 分钟的成功快照。
- 第一阶段定时任务按整点、半点运行；若电脑休眠、BI登录失效或导出超时，则该次更新失败并保留上一版。下一次成功更新若错过30分钟窗口，会回退到2小时内最近一次快照，并标注真实间隔，不伪装成30分钟。
- 金额增量为当前金额减历史金额；门店排名变化为历史名次减当前名次。
- 没有可比快照时显示“等待下一次更新”，不填 0、不做推测。
- 最快门店按近30分钟新增金额降序。
- 待督促门店仅从挑战目标有效且尚未达成的门店中选择，先按近30分钟增长升序，再按当前挑战达成率升序。
- 区域达成率使用区域金额合计除以区域目标合计，不平均门店百分比。

## 失败保护

- 解析脚本只有在完整解析成功后才覆盖 `public/data/report.json`。
- 任一导出失败、5＋2张关键工作表缺失、门店／职能数据异常或构建失败时停止发布，保留上一版线上数据。
- 页面超过45分钟未更新会显示“数据已延迟”。
- BI集团总计与“门店端＋职能端”分项差异超过1%时显示校验提醒；页面仍保留最后一次通过完整校验的数据。

## 不公开的文件

- `data/raw/`：BI原始 Excel。
- `data/snapshots/`：完整本地历史快照。

当前两份轻量导出合计约50KB、计算快照约22KB。即使每天48次，806活动期本地文件量仍很小；网页端始终只加载最新一份约100KB的 `report.json`，不会把全部历史塞进手机缓存。

公开仓库只包含页面需要的 `public/data/report.json`。即使关闭复制和右键，公开网页数据仍可被截图或通过开发者工具读取。
