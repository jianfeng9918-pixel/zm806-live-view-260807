# 806 战报第一阶段刷新操作手册

## 用户需要做什么

1. 在 Chrome 登录周麻婆 BI。
2. 每半小时对 Codex说“更新806战报”。
3. 若登录失效、出现验证码或 BI 改版，由用户完成登录或确认，不向 Codex提供密码、验证码。

## Codex 更新步骤

1. 打开 `15_2026版_806活动储值分析`。
2. 进入“导出 → 批量导出 Excel”，选中全部可导出图表并下载完整工作簿。
3. 核对工作簿必须包含门店累计、门店今日、门店目标与奖金、区域今日、区域目标与奖金等关键工作表；禁止用当前屏幕可见行替代完整导出。
4. 将工作簿放入 `data/raw/`，使用 BI 导出完成时间作为 `generated-at` 运行：

   ```bash
   npm run data:update -- --input data/raw/806-export-YYYYMMDD-HHmm.xlsx --generated-at YYYY-MM-DDTHH:mm:ss+08:00
   npm run verify
   ```

5. 检查生成摘要中的门店数、区域数、总部今日金额、总部累计金额、已达标区域和数据对账状态。
6. 在 393px 手机视图核对总部、一个区域、一个门店、搜索和今日／累计切换。
7. 提交并推送到 `main`，等待 GitHub Pages 部署成功。

## 近30分钟口径

- 当前快照会匹配距它 20–40 分钟内、时间最接近 30 分钟的成功快照。
- 金额增量为当前金额减历史金额；门店排名变化为历史名次减当前名次。
- 没有可比快照时显示“等待下一次更新”，不填 0、不做推测。
- 最快门店按近30分钟新增金额降序。
- 待督促门店仅从挑战目标有效且尚未达成的门店中选择，先按近30分钟增长升序，再按当前挑战达成率升序。
- 区域达成率使用区域金额合计除以区域目标合计，不平均门店百分比。

## 失败保护

- 解析脚本只有在完整解析成功后才覆盖 `public/data/report.json`。
- BI导出失败、关键工作表缺失、门店数量异常、构建失败时停止发布，保留上一版线上数据。
- 页面超过45分钟未更新会显示“数据已延迟”。
- BI官方汇总与门店合计差异超过1%时显示校验提醒，并继续保留BI官方汇总值。

## 不公开的文件

- `data/raw/`：BI原始 Excel。
- `data/snapshots/`：完整本地历史快照。

公开仓库只包含页面需要的 `public/data/report.json`。即使关闭复制和右键，公开网页数据仍可被截图或通过开发者工具读取。
