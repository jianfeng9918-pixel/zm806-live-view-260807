# 806 战报第一阶段刷新操作手册

## 用户需要做什么

1. 在 Chrome 登录周麻婆 BI。
2. 保持电脑开机、联网，并让 Chrome 中的 BI 登录保持有效；定时任务将在整点和半点自动执行。
3. 若登录失效、出现验证码或 BI 改版，由用户完成登录或确认，不向 Codex提供密码、验证码。

## Codex 更新步骤

1. 打开 `15_2026版_806活动储值分析`。
2. 进入“导出 → 批量导出 Excel”，只选择下列5张战报必需表，禁止点击“全选”：
   - `门店_总储值目标达成率`
   - `门店_今日目标达成率排行`
   - `门店_目标达成与奖金`
   - `销售地区_今日储值目标达成率`
   - `销售地区_目标达成与奖金`
3. 使用“直接导出 → 保存为多个sheet”，导出1个轻量Excel。正常约几十KB；超过5MB或超过8张工作表会被自动拒绝。
4. 核对工作簿必须包含100家以上门店和10个以上区域；禁止用当前屏幕可见行或截图替代完整导出。
5. 定时任务将下载文件交给以下入口，成功后原下载文件移入废纸篓，原始副本和计算快照保留在本地且不公开：

   ```bash
   npm run data:ingest -- --input "/Users/huangjianfeng/Downloads/本次导出文件.xlsx" --trash-source
   ```

6. 入口会自动执行完整验证，检查门店数、区域数、总部金额、数据对账、规则与构建；任一步失败都不发布。
7. 成功后仅更新公开网页所需的 `public/data/report.json`，GitHub Pages完成发布后，已打开的手机页面会在1分钟内发现新版本并刷新数据。

## 近30分钟口径

- 当前快照优先匹配距它 20–40 分钟内、时间最接近 30 分钟的成功快照。
- 第一阶段定时任务按整点、半点运行；若电脑休眠、BI登录失效或导出超时，则该次更新失败并保留上一版。下一次成功更新若错过30分钟窗口，会回退到2小时内最近一次快照，并标注真实间隔，不伪装成30分钟。
- 金额增量为当前金额减历史金额；门店排名变化为历史名次减当前名次。
- 没有可比快照时显示“等待下一次更新”，不填 0、不做推测。
- 最快门店按近30分钟新增金额降序。
- 待督促门店仅从挑战目标有效且尚未达成的门店中选择，先按近30分钟增长升序，再按当前挑战达成率升序。
- 区域达成率使用区域金额合计除以区域目标合计，不平均门店百分比。

## 失败保护

- 解析脚本只有在完整解析成功后才覆盖 `public/data/report.json`。
- BI导出失败、关键工作表缺失、门店数量异常、构建失败时停止发布，保留上一版线上数据。
- 页面超过45分钟未更新会显示“数据已延迟”。
- BI官方汇总与门店合计差异超过1%时显示校验提醒，并继续保留BI官方汇总值。

## 不公开的文件

- `data/raw/`：BI原始 Excel。
- `data/snapshots/`：完整本地历史快照。

当前轻量导出约43KB、计算快照约22KB。即使每天48次，原始文件与快照合计约3MB；806活动期总量通常低于50MB。网页端始终只加载最新一份约100KB的 `report.json`，不会把全部历史塞进手机缓存。

公开仓库只包含页面需要的 `public/data/report.json`。即使关闭复制和右键，公开网页数据仍可被截图或通过开发者工具读取。
